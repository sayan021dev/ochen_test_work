# Инструкции для агентов

## Цель и текущий этап

Тестовое задание для Junior AI Developer в продукт Снэпбилд студии Очень.
Создаём веб-конструктор, автоматически собирающий векторные иллюстрации
из предоставленных объектов по метафоре/заголовку или названиям компонентов.

10 ноября 2026 пользователь одобрил реализацию локальной V1 по предложению,
коммиты и push непосредственно в `main`, а также OpenAI API с небольшой дешёвой моделью.
Обязательны регрессионные, модульные и сквозные проверки Playwright.
Реальные AI-вызовы требуют ключ в локальном окружении; секреты в чат не запрашивать.
Серверный этап следует за локальной приёмкой.

## Обязательные ограничения продукта

1. Только исходные иллюстративные объекты из предоставленной библиотеки.
   AI разбирает смысл и выбирает существующие ID, но не создаёт SVG, контуры или картинки.
2. Не менять геометрию и внутренние элементы объектов. Не растрировать результат.
   Сохранять группы, контуры, обводки, маски и локальные ссылки SVG.
3. Сохранять исходные пропорции и относительные размеры при автоматической сборке.
   10 ноября пользователь явно добавил ручной ресайз и растяжение рамкой:
   углы изменяют размер пропорционально, боковые ручки — по одной оси.
   Это отдельные трансформации экземпляра, оригинальные SVG не переписываются.
4. S и L являются разными наборами детализации, а не только CSS-размерами.
   Выбор размера должен переключать реальные исходные варианты.
5. Главный цветной и фоновый монохромный объект являются вариантами одного предмета.
   Замена варианта не должна терять положение, угол и порядок слоя.
6. Три исходные схемы плюс импорт пользовательской палитры.
   Цвета фонов допустимы в объектах, цвета объектов недопустимы в фонах.
   Перекрашивать по ролям цветов, не по близости RGB и не заменой всего на один цвет.
7. Экспортировать самостоятельный SVG с редактируемыми группами объектов.
   Никаких внешних зависимостей, скриншотов, временных URL Figma или UI-рамок в экспорте.
8. Оба сценария автоматической сборки обязательны уже для первой полной версии.

## Архитектурные ориентиры

- Backend зафиксирован пользователем: Python + FastAPI.
- Предлагаемый frontend: React + TypeScript + Vite, нативный SVG.
- Предлагаемое хранение: PostgreSQL, SQLAlchemy, Alembic для проектов;
  SVG и каталог метаданных версионируются как файлы.
- Один FastAPI-сервис с небольшими предметными модулями, без микросервисов.
- Scene JSON с версией схемы является состоянием редактора. Хранить ID исходного
  asset, размер, роль, положение, угол, порядок и палитру; не HTML или произвольный SVG от AI.
- FastAPI проверяет каталог, ограничения сцены и палитры перед сохранением/экспортом.
- Figma нужна для подготовки библиотеки, но не для запуска сервиса у проверяющего.
- Redis, RabbitMQ, S3, биллинг и сложную авторизацию добавлять только под конкретный сценарий.
- Точные версии и lock-файлы фиксировать при реализации после проверки совместимости.

## Работа с SVG и безопасностью

- Сохранять неизменённые оригиналы отдельно от производных файлов.
  Для каждого asset фиксировать Figma node ID, вариант, размеры, хеш и происхождение.
- Проверять полноту объектов визуально: часть исходных контуров может лежать вне именованной группы.
- Пространства ID для `defs`, `clipPath`, масок и градиентов разделять по экземплярам.
- Не переписывать path data, не упрощать контуры ради размера файла.
- Запрещать scripts, обработчики событий, `foreignObject`, внешние URL,
  DTD/сущности XML и растровые вложения. Ограничивать размер, глубину и число узлов.
- SVG от пользователя не исполнять; в V1 использовать подготовленный каталог.
- Ключи AI только на backend через окружение. Не передавать браузеру и не логировать.
- Публичные AI-запросы ограничивать по частоте, параллельности и бюджету.
- При ошибке AI сохранять текущую сцену и честно показывать режим/ошибку.
  Словарный деморежим не выдавать за работу LLM.

## Визуальный язык

- Ориентир: [snapbuild.ru](https://snapbuild.ru/), а не точная копия маркетинговой страницы.
- Тёмные серые поверхности, спокойные границы, розовый акцент `#FF68A4`;
  проверенный фон сайта `#1D1D20`.
- Inter для UI, TikTok Sans для заголовков. Брать из официальных источников с лицензиями.
- Палитра оболочки редактора отделена от палитры экспортируемой иллюстрации.
- Русский интерфейс, видимые состояния загрузки/ошибок/сохранения, доступные кнопки и клавиатура.
- Предлагать улучшения через пользу для сценария и критерий приёмки.

## Порядок разработки и проверки

- Делать законченные шаги: библиотека/экспорт, ручной редактор, автосборка,
  AI-разбор, палитры/размеры, сохранение, полировка и сдача.
- До разработки соответствующего шага записать его проверяемый результат.
- Тестировать риски: геометрия/пропорции, SVG ID, роли палитр, оба режима генерации,
  недоступность AI, экспорт и восстановление после перезагрузки.
- Backend: pytest + HTTPX; frontend: Vitest/Testing Library; сквозные сценарии: Playwright.
- Проверять экспорт повторным импортом в Figma или Inkscape, включая редактируемость групп.
- Не считать успешную сборку доказательством качества иллюстраций.
  Проводить визуальную проверку S/L, трёх схем и трёх форматов.
- Тесты с подставным AI выполнять без оплаты; реальные вызовы нужны для финальной проверки интеграции.
- Команды запуска и проверок добавить в README одновременно с рабочими конфигами.
  Пока приложения нет, не писать, что команды или тесты уже работают.

## Git, публичный репозиторий и сдача

- Пользователь явно выбрал работу непосредственно в `main` и push после законченных шагов.
  Не создавать ветки/worktree вместо этого без причины.
- Перед коммитом просмотреть diff, выполнить подходящие проверки, проверить состав файлов.
- Коммиты небольшие, осмысленные: `docs:`, `feat:`, `fix:`, `test:`, `chore:`.
- После push проверить соответствие локального и удалённого коммита.
- Не делать force push, не перезаписывать чужие изменения, не коммитить секреты,
  резюме, контакты, реальные пользовательские данные или содержимое других приватных проектов.
- `presentations-b2c` использовать как read-only технический ориентир;
  не переносить его код/ассеты/конфигурацию в публичный проект без отдельного разрешения.
- Не распространять лицензию нашего кода автоматически на исходные иллюстрации и брендовые материалы.
- Подготовить README с запуском, архитектурой хранения/извлечения/переиспользования SVG,
  ограничениями, перечнем реально использованных AI-инструментов и 2–3 примерами.
- Деплой через Termius готовить после локальной приёмки; сервер и домен пока не выбраны.
  Перед изменениями подтвердить хост, отдельный каталог/compose-проект, порты, сохранность данных
  и способ отката. Статус контейнера отделять от проверки работающего приложения.

## Одобренное дополнение: «Своя тень»

10 ноября пользователь одобрил отдельный opt-in режим поверх основного функционала.
Обычные SVG/экспорт остаются исходными. В режиме эффекта допустимы производные маски,
трансформации исходного отпечатка тени и замыкающий контур боковой стенки монеты для отделения слитой тени.
Это не разрешение менять файлы оригиналов/библиотеки или перерисовывать новые предметы.
Сохранить режим отдельным, отключённым по умолчанию, и проверять preview/export parity.

Пользователь уточнил: работать именно с исходной чёрной тенью, без второй проекции
силуэта предмета. Ноль градусов, длина/непрозрачность 100% и нулевое смещение
сохраняют оригинал. Тень можно выбрать отдельно и трансформировать рамкой.
Скрытая за предметом часть исходной тени не восстанавливается выдуманными контурами.
Блокировать только явное переназначение LLM/посторонние команды; обычные,
технические, абстрактные и вопросительные темы принимать через ближайшую метафору.
Пароль проверяющих задаётся SITE_PASSWORD; на публичном деплое обязательны
REQUIRE_SITE_PASSWORD=true, стабильный AUTH_SECRET и COOKIE_SECURE=true под HTTPS.

## Уточнение 10 ноября: раскладка и закреплённая тень

- Сохранять явно заданные пространственные отношения во всех трёх вариантах.
  Простые названные предметы не заменять фоновыми только из-за их номера в списке.
- Проверять точный набор разобранных отношений, а не только наличие ожидаемых:
  лишняя связь тоже является ошибкой. Для обычной раскладки запрещены пересечения
  полных границ исходных SVG; контакт допускается по явному on/behind/front запросу.
- Пользователь разрешил дополнить opt-in тень заполненным SVG-соединением между
  закреплённой границей контакта и преобразованным внешним отпечатком.
  Это заменяет прежнее свободное отсоединение отпечатка. Измерение границы на этапе
  подготовки допускается растровым образцом; продукт/экспорт остаются векторными.
- Общий нижний проход теней не должен включать художественные исправления у обычных
  предметов. Проверять сохранность исходных непрозрачных областей и прозрачного внешнего
  пространства на всех 40 вариантах; учитывать отдельные различия сглаживания краёв.
- Параллельные Playwright-прогоны используют разные output-каталоги, иначе очистка
  артефактов одним runner ломает trace другого. Финальный полный прогон — один.


## Новое уточнение: проекция силуэта, 10 ноября

Пользователь заменил прежний способ своей тени: теперь разрешена чёрная векторная
копия тела предмета, проецируемая на плоскость от неподвижной линии опоры. Это
переопределяет требование «только исходный отпечаток» и прежнюю сетку соединений.
Сохранять поперечные пропорции, просветы силуэта и закрывать тень телом/основанием.
Смещение/рамка управляют направлением и длиной проекции, не отсоединяют её от предмета.
Обычный режим и неизменяемые файлы исходников сохраняют прежние ограничения.

## Тени на опорах и выключаемый свет

Новое уточнение пользователя: обычная тень предмета должна попадать на явно заданные
опоры («ручка на лампе», «лампа на телефоне») независимо от экспериментального режима.
Scene JSON v1 хранит support_ids экземпляров, проверяет граф и порядок; несколько
опор нельзя терять. Тени обрезаются фактической альфой тел и видимостью поверхностей,
не bbox. Перемещения сохраняют ссылки; удаление/clipboard/смена порядка не оставляют
некорректных ссылок. У обычных несвязанных предметов сохраняется прежняя защита от
непреднамеренного затенения.

Общий источник света — отдельная 2D-имитация в SVG: положение/высота/плотность,
исходные блики предметов не перестраиваются. Глобальный режим не должен перезаписывать
сохранённые индивидуальные shadow-параметры даже при трансформации объектов.
CUSTOM_SHADOWS_ENABLED=false скрывает все экспериментальные взаимодействия и
игнорирует их в превью/экспорте, сохраняя данные для повторного включения. Контактные
тени на опорах при этом остаются. Пока пользователь не попросил выключить эксперимент,
локально оставлять default true. После смены env нужен перезапуск и refresh.


## Обычный редактор и экспериментальная мастерская

Последнее уточнение пользователя (10 ноября) переопределяет доступность теней:
общий свет и «Своя тень» доступны только после явного входа в экспериментальный
режим. При открытии/перезагрузке всегда обычный режим; сохранённые параметры
света/тени не включают его автоматически и не теряются при выходе. Серверный
SVG-экспорт по умолчанию обычный; эксперимент требует query experimental=true
и включённый CUSTOM_SHADOWS_ENABLED. Галерея показывает обычные превью.

При входе открывается пошаговая инструкция с настоящими скриншотами редактора,
стрелками, подсвеченными кнопками, переходами назад/вперёд и действием «Показать
в редакторе». Её можно открыть повторно. Не выдавать 2D-имитацию за 3D-освещение.

Обычные тени на явно заданных опорах остаются независимо от режима. У поднятого
предмета не рисовать остаток локальной тени в воздухе вне опоры. Сохранять
непрозрачные детали самого предмета и тень предмета нижнего уровня на плоскости.
Проверять реальные композиции S/L, пиксели контакта, отсутствие воздушных остатков
и совпадение preview/export; оригиналы SVG не менять.

Пользователь добавил проверку по исходным примерам композиций Figma. Отдельно
сравнить исходные геометрию/цвета и результат алгоритма; перенос координат из
эталона нельзя выдавать за автоматическую генерацию «один в один».

11 ноября: допустимые составные behind/front-запросы нельзя отклонять лишь потому,
что предпочтительное выравнивание центров несовместимо с разнесением других
предметов. Сначала сохранять прежнюю раскладку; при неудаче разрешать смещение
behind/front с положительным пересечением границ. Контакт on, относительные
направления, непересечение несвязанных пар и порядок слоёв не ослаблять.

## Крупность и обычные тени, 11 ноября

Пользователь попросил обобщить художественные приёмы примеров Figma: крупный план,
кадрирование, фоновые роли и цвета, без готовых координат и раскладок для отдельных
семейств. Сохранять единый масштаб исходных размеров и явные пространственные связи.
Scene v1 дополнен framing и color_map по ролям палитры; старые проекты допустимы.
Намеренный кадр не сбрасывать в обычное вписывание при смене формата.

Новое требование обычных теней переопределяет защиту несвязанных предметов выше:
исходный отпечаток верхнего слоя попадает на фактические видимые поверхности ниже.
Просветы и верхние непрозрачные слои закрывают его по альфе. У несвязанных предметов
сохраняется исходный отпечаток на плоскости; явно заданные support_ids ограничивают
приёмники и убирают воздушный остаток. Это 2D-послойная имитация, не 3D-свет.
Экспериментальный режим и деплой пользователь оставил следующему этапу.

После каждого крупного блока обновлять README, особенно реальные фото-примеры.
Сохранять прежние неуспешные когорты аудита рядом с новой проверкой.

Контакт `on` теперь совмещает исходную опору предмета с внутренней поверхностью
приёмника. `assets/contact-map.json` вычисляется из реальных тел SVG скриптом
`scripts/prepare_contact_metadata.mjs` и привязан к хешам. Это не координаты сцен.
Проверять физический контакт, а не устаревшие условия «верх SVG выше опоры» или
«центры полных SVG совпадают»: у плоского предмета начало может лежать внутри книги.
Новые фото, JSON-примеры и результаты находятся в README и docs/ART_DIRECTION_ACCEPTANCE.md.
