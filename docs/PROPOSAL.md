# Предложение по реализации

> Исторический документ подготовки. Актуальный результат: [принятая V1](V1.md),
> [финальная проверка](ART_DIRECTION_ACCEPTANCE.md), [production-выпуск](RELEASE.md).

Статус: одобрено пользователем 10 ноября 2026 года, начата локальная реализация.
Дополнение: обязательны регрессионные/модульные тесты и Playwright;
пользователь также одобрил OpenAI API с небольшой недорогой моделью.

## Результат первой полной версии

Веб-редактор на русском языке. Пользователь вводит метафору/заголовок либо названия
предметов, выбирает формат, детализацию и палитру, получает автоматически собранную
композицию, редактирует её и скачивает самостоятельный SVG.

V1 покрывает все требования R01–R15 из [исследования](RESEARCH.md).
Развитие сверх ТЗ идёт после этого. Предлагаемые допущения: однопользовательское
редактирование, настольный браузер как основной сценарий, доступ без регистрации,
подготовленная библиотека вместо загрузки произвольных SVG посетителями.

## Варианты и рекомендуемый стек

| Вариант | Плюсы | Цена для этой задачи |
|---|---|---|
| **FastAPI + React/TypeScript/Vite + нативный SVG** | Прямое управление исходным вектором, небольшой frontend, Python отвечает за всю серверную логику | Требуется аккуратно реализовать выделение и трансформации |
| FastAPI + Next.js + нативный SVG | Знакомый стек, встроенная маршрутизация, подходит при большом публичном сайте | Серверный рендеринг не помогает интерактивному холсту; появляется второй серверный runtime при стандартном SSR-развёртывании |
| FastAPI + React + Fabric.js/Konva | Готовые механики интерактивного Canvas | Надо отдельно доказывать сохранность SVG при импорте/экспорте; Canvas не является самим векторным документом |

Одобрен первый вариант.
Плагин Figma допустим по ТЗ, но не соответствует выбранному пользователем формату
самостоятельного сайта с Python backend.

Предлагаемые инструменты: Python/FastAPI/Pydantic, SQLAlchemy/Alembic/PostgreSQL;
React/TypeScript/Vite, TanStack Query для API, небольшой Zustand-store для редактора;
CSS с токенами темы, Lucide для служебных иконок. Иконки UI не попадают в иллюстрации.
Проверки: pytest/HTTPX, Vitest/Testing Library, Playwright, Ruff/ESLint/TypeScript.
Точные версии и необходимость каждой зависимости фиксируются при создании каркаса.

## Предметные модули и зависимости

| ID | Ответственность | Зависит от |
|---|---|---|
| asset-catalog | Оригиналы SVG, происхождение, S/L, роли и цветовые слоты | — |
| scene-core | Схема сцены, правила палитры/размеров, экспорт | asset-catalog |
| composition | Подбор предметов, AI-разбор, автоматическая компоновка | scene-core |
| editor | UI, ручные операции, undo/redo, варианты композиций | scene-core, composition |
| persistence | Сохранение и восстановление проектов | scene-core |
| delivery | Docker, CI, документация, примеры и будущий деплой | Остальные модули |

Это модули одного приложения, а не отдельные сервисы.
Порядок: каталог → валидная сцена/экспорт → ручной редактор → автокомпоновка
→ AI → все варианты размеров/палитр → сохранение → приёмка и сдача.

## Как сохраняем исходный вектор

При подготовке библиотеки экспортируем предметные группы из Figma, отдельно S/L
и главные/фоновые варианты. Сохраняем оригиналы и каталог:
`asset_id`, `family_id`, `detail`, `role`, `source_node_id`, исходные размеры,
`viewBox`, хеш, словарь смыслов/синонимов, роли заливок/обводок.

Сначала визуально проверяем несколько сложных объектов и отдельные контуры рядом
с группами. Затем закрываем весь каталог. Декоративные элементы также имеют источник.
Объект не разбирается на заново нарисованные фигуры и не упрощается.

В базе сохраняется Scene JSON с версией схемы, ID объектов, позицией, поворотом,
порядком слоёв, размером S/L, схемой и общим масштабом сцены.
Относительные размеры берём из конкретного исходного набора; не нормализуем
книгу и монету до одинаковой ширины. При смене S/L сохраняем смысловой состав
и переносим опорные точки, а размеры берём из соответствующих SVG.

Preview использует исходные SVG-группы с внешними transform.
Backend строит экспорт из того же каталога и Scene JSON. Каждый экземпляр получает
уникальные ID для масок/градиентов/clipPath; экспорт содержит собственные определения
и группы, без внешних `<image>` и без зависимости от сервера или Figma.
Совпадение preview/экспорта проверяем на одних и тех же сценах.

## Как работает автоматическая сборка

**Сценарий компонентов.** Поиск по именам/синонимам → точные ID → выбор ролей
→ раскладка на выбранном формате. Неизвестный предмет показываем как недоступный;
не подменяем молча другим.

**Сценарий метафоры.** Модель получает небольшой семантический каталог и запрос,
возвращает только структурированные данные: выбранные `family_id`, роли и краткое
объяснение связи с запросом. Backend проверяет ID, количество, схему и допустимые роли.
AI не имеет инструмента рисования, произвольного SVG или выполнения кода.

**Компоновка.** Небольшой набор выверенных раскладок по мотивам предоставленных
примеров: главный объект с поддержкой, диагональ, группа, акцент на переднем плане.
Правила учитывают реальные габариты, safe area, порядок слоёв, заметность главного
объекта и допустимое декоративное кадрирование. Seed даёт повторяемость.
Метафора определяет предметы и смысловой приоритет, код отвечает за геометрию.

Предлагаемый пример: «Собрать знания в систему» → книга, пазлы и ручка.
Это пример для будущего тестирования, а не уже полученный результат.
Если библиотека не выражает запрос, интерфейс объясняет ограничение и предлагает
доступные предметы; не обещает точное воплощение любой метафоры.

Один AI-провайдер с конфигурацией через окружение. Ограниченный timeout,
обработка сетевой ошибки/некорректного ответа и защита от повторной отправки.
Без ключа доступны редактор, режим предметов и явно обозначенные словарные демопримеры;
полноценный сценарий метафоры принимаем только после проверки реального API.
Провайдера и модель согласуем до платных вызовов.

## Палитры и размер

Встроены три проверенные схемы. Пользовательская палитра загружается JSON-файлом
с именованными слотами `background[4]` и `object[4]`; в UI есть пример файла и
понятная ошибка при неверном формате. Такой формат закрывает загрузку палитры
однозначно; импорт ASE/изображения можно добавить позже.

Перекраска изменяет только значения утверждённых цветовых слотов в производном SVG.
Исходники остаются неизменными. Прозрачность, контуры и назначение цветов сохраняются.
Цвета объектов запрещены в фоне. При повторном переключении палитр нет накопления
погрешностей: всё вычисляется от оригинала и текущей карты ролей.

Три формата: 1000×1000, 1200×630, 800×1200. Детализация S/L выбирается отдельно
от соотношения сторон. Независимый resize отдельных предметов в V1 не предлагаем:
на странице примеров прямо запрещено менять относительные пропорции объектов.

## Интерфейс

Основной экран сразу открывает редактор. Слева: запрос, переключатель двух сценариев,
поиск и библиотека предметов. По центру: SVG-холст и предварительный результат.
Справа: слои, роль выбранного объекта, угол/позиция, формат, S/L и палитра.
Сверху: название проекта, сохранение, undo/redo, экспорт.

Сдержанная тёмная оболочка по мотивам Snapbuild: Inter, TikTok Sans,
серые поверхности и розовые активные состояния. Цвета схем иллюстраций независимы.
Ручные операции мышью и с клавиатуры; понятное выделение, zoom/fit,
подсказки, загрузка, ошибки, пустые результаты и статус сохранения.
На узком экране панели сворачиваются; полный редактор сначала принимаем на desktop.

## Хранение, API и запуск

PostgreSQL хранит проекты, Scene JSON, пользовательские палитры и версию сохранения.
Оригиналы/производные SVG и метаданные каталога лежат в репозитории; S3 не нужен V1.
Для нескольких вкладок сохраняем с проверкой версии, конфликт показываем пользователю.

Предлагаемый API: каталог/палитры; подбор/композиция; создание/чтение/обновление
проекта; SVG-экспорт; health/readiness. Pydantic проверяет границы и данные,
OpenAPI документирует запросы. Точные маршруты и схемы определим после одобрения.

Без обязательного логина: проекты привязаны к непрозрачной серверной сессии
в HttpOnly-cookie; чужие проекты недоступны по перебору ID. Демопримеры общие,
но не изменяются посетителем. Для AI вводим лимиты запросов, длины, параллельности
и общего расхода. CORS ограничен нашим origin, записи защищены от CSRF.
Сырые тексты запросов и ключи в стандартные логи не попадают.

Предлагаемая структура: `backend/`, `frontend/`, `assets/`, `scripts/`, `tests/e2e/`,
`docs/`, `examples/`, compose-файл. Локально: Docker Compose для backend,
PostgreSQL и отдачи frontend. Для разработки допускается Vite с proxy `/api`.
Команды будут добавлены вместе с реальными конфигурациями, сейчас они не существуют.

## Этапы и критерии готовности

| Этап | Результат | Проверка перед следующим шагом |
|---|---|---|
| 1. Каталог и экспорт | Все семейства, S/L, роли, три схемы; минимальная сцена → SVG | Сверка сложных исходников, хешей, размеров, ID и повторный импорт SVG |
| 2. Сквозной ручной сценарий | Добавить два предмета → переместить/повернуть/слои → скачать | E2E и редактирование отдельных групп в Figma/Inkscape |
| 3. Автосборка | Оба режима, правила раскладки, реальные AI-ответы | Набор метафор, точных/неизвестных названий, ошибок API; смысловая и визуальная оценка |
| 4. Варианты | Три формата, S/L, главные/фоновые, три схемы и JSON-палитра | Матрица вариантов, корректная перекраска без изменения геометрии |
| 5. Сохранение и UX | Восстановление после reload, undo/redo, статусы, клавиатура | E2E полного пути, конфликт вкладок, изоляция сессий |
| 6. Сдача локальной V1 | Воспроизводимый запуск, CI, README, демо и 2–3 SVG-примера | Чистая установка по инструкции и ручная приёмка пользователя |
| 7. Сервер | Домен, TLS, сохранение данных, запуск через Termius | Проверка публичного пути до экспорта, readiness, persistence и отката |

Для этой задачи важнее результаты, чем процент покрытия. Обязательные проверки:
неизменность path data, отсутствие растра/внешних ссылок, независимые SVG ID,
верные размеры/слои/палитры, восстановление, неизвестные ID AI и безопасный XML.
Backend/frontend проверки и сборка идут в GitHub Actions после появления кода.
Офлайн-тесты используют подставного провайдера, реальные вызовы отдельны и ограничены.

## Полезные улучшения после покрытия ТЗ

1. Несколько вариантов композиции с тем же набором предметов и объяснением выбора.
2. Пересборка выбранной сцены под три формата с сохранением смыслового акцента.
3. Панель происхождения: предмет, исходный node, детализация и роль.
4. Галерея сохранённых работ и аккуратная демонстрация работы AI.

Undo/redo, сохранение и клавиатура уже предложены в V1 как небольшие улучшения UX.
PNG-превью допустимо для галереи/демо, но не заменяет SVG-экспорт.
Регистрация, оплата, командная работа и произвольный SVG-импорт не входят в V1.

## Что уточнить для окончательной оценки

- Есть ли срок сдачи: от него зависит объём улучшений сверх обязательного ТЗ.
- Какой AI API уже доступен и какой допустим бюджет интеграционных проверок.
- После локальной приёмки: домен, сервер и отдельное место развёртывания.

Самый ранний технический риск: корректно извлечь все части исходных объектов
и зафиксировать цветовые роли. Его проверяем первым, до глубокой разработки UI.
Оценку длительности уточним после проверки экспорта нескольких сложных объектов.
