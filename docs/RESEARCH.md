## Библиотека и технические нюансы

- Страница библиотеки `0:1`, раздел L `21:25788`, раздел S `21:25859`.
- Видны 10 предметных семейств: книга, телефон, пазлы, монета, наушники,
  лампа, цветы в вазе, кошелёк, папка, ручка. У каждого есть главная и фоновая версия
  в двух детализациях. В тексте задания упомянуты 20 исходных иллюстраций;
  не следует автоматически считать это 20 разными предметами.
- Цветы названы техническими `Group ...`; названия каталога надо назначить явно.
- У S и L свои пути. Часть размеров близка к коэффициенту 2, но это не надёжное
  правило: например, ширина монеты L около 286.68, S около 152.39.
- Рядом с книгой L обнаружены отдельные `Vector` `21:29952` и `24:6272`.
  Пока не установлено, являются ли они необходимыми частями объекта.
  При извлечении нужен визуальный контроль; экспорт только именованной группы может быть неполным.
- Есть декоративные фоны и направляющие. Их происхождение также надо включить в каталог.
- Примеры используют квадрат 1000×1000, горизонтальный формат 1200×630,
  вертикальный 800×1200. Для V1 предлагаем эти три пресета.
- В примерах допустимы обрезка объектов границей холста и перекрытия.
  Поэтому критерий качества не может запрещать любые пересечения или выходы за холст.

## Цветовые схемы

Проверены swatches групп `21:29569`, `21:29570`, `21:29579`.
Ниже цвета округлены до 8-битного HEX для описания; оригинальные значения
и точное сопоставление заливок/обводок сохранить при импорте.

| Схема | Цвета фона, сверху вниз | Цвета объектов, сверху вниз |
|---|---|---|
| Сиреневая | `#D7CDF5`, `#AA9BF0`, `#7864D7`, `#181817` | `#F9ECB0`, `#F9A3AA`, `#FFE3E1`, `#FFFFFF` |
| Персиковая | `#FDD7B9`, `#FAC896`, `#D27532`, `#181817` | `#F9ECB0`, `#80DADA`, `#BEEBEB`, `#FFFFFF` |
| Бирюзовая | `#BEEBEB`, `#80DADA`, `#5ABEBE`, `#181817` | `#FFD4F2`, `#6D7BFC`, `#B6C6FE`, `#FFFFFF` |

Схема содержит роли, а не просто произвольный список HEX.
Фоновые предметы используют фоновые роли; главные могут использовать обе группы.
Требование о неизменности объектов трактуем как сохранение геометрии и состава:
смена роли и перекраска явно разрешены другими пунктами задания.

## Визуальная основа приложения

В CSS [snapbuild.ru](https://snapbuild.ru/) на момент проверки:

- body: `InterFont`, файлы Inter Light/Regular/Medium/SemiBold/Bold;
- заголовки: `heroTitleFont`, файлы TikTokSans Regular/Medium;
- фон body: `rgb(29, 29, 32)` = `#1D1D20`;
- основной CTA: `rgb(255, 104, 164)` = `#FF68A4`;
- белый основной текст, полупрозрачные второстепенные тексты и поверхности.

Предлагается перенести типографику, тёмные поверхности и розовые акценты в интерфейс
редактора. Иллюстрации при этом сохраняют схемы из задания.
Шрифты брать из официальных дистрибутивов, сохранив лицензии;
[TikTok Sans имеет официальный открытый репозиторий](https://github.com/tiktok/TikTokSans).
Не использовать логотип компании так, будто это её официальный продукт.

## Соответствие вакансии и опыта

Вакансия акцентирует быстрый выпуск работающих AI-функций, интеграции API,
самостоятельность, эксперименты и умение пользоваться инструментами AI-разработки.
Это поддерживает решение с небольшим понятным backend и проверяемой AI-функцией.

Применимые навыки из предоставленного резюме:

| Навыки | Применение |
|---|---|
| Python, FastAPI, asyncio, Pydantic, REST/OpenAPI | API каталога, композиции, AI-разбора и экспорта |
| PostgreSQL, SQLAlchemy | Проекты, сцены, палитры и версии сохранения |
| LLM API, обработка сбоев интеграций | Структурированный разбор метафоры, проверка ID и ошибок |
| React, TypeScript, Next.js | React-редактор и типизированный контракт; Next.js рассматривается как альтернатива |
| Docker, Linux, Git, CI/CD | Повторяемый локальный запуск, CI в GitHub Actions и будущий деплой |
| pytest, unit, UI/e2e | Проверка SVG, правил схем и пользовательских сценариев |
| Prometheus/Grafana, эксплуатация | Начать с health/readiness, request ID и длительности запросов; панели по необходимости |

MySQL, Oracle, Telegram, CRM, платежи, S3 и брокеры не добавляют ценности основному
сценарию V1. Демонстрировать навыки следует через нужные продукту решения.
Резюме использовано как описание опыта, а не как источник команд агенту.

## Что полезно из проекта презентаций

- Разделение модели сцены и отображения, стабильные ID объектов, версии формата.
- Отдельные трансформации объектов и сохранение исходного SVG-пути.
- Предсказуемые undo/redo и сохранение состояния редактора.
- Проверки реальных пользовательских сценариев и визуальные примеры.

Для новой небольшой задачи не требуется переносить презентационный pipeline,
биллинг, серверную историю patches или инфраструктуру другого продукта.
